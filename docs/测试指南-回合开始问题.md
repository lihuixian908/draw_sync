# 测试指南 - 修复"画家显示回合未开始"问题

本文记录当时的修复和日志示例。当前版本可按 [双人联机验证](../README.md#双人联机验证) 创建房间和开始游戏。

## 问题描述
当玩家可以猜词时（猜词者身份），画家（另一个客户端的画手）显示"等待回合开始"，无法绘画。

## 修复内容

### 1. 增强消息接收日志
在 `mainwindow.cpp` 的消息处理中添加详细日志：
```cpp
if (msg.startsWith("round_start drawer:")) {
    qDebug() << "*** 关键消息 *** 收到回合开始，drawerId:" << drawerId 
             << "我的playerId:" << m_playerId 
             << "我的playerName:" << m_playerName;
}
```

### 2. 改进身份判断逻辑
使用多种方式匹配画手身份，避免因ID格式问题导致判断失败：
- 精确匹配 `player_id`
- `drawerId` 包含 `playerId`
- `drawerId` 包含 `playerName`
- `playerId` 包含 `drawerId`（反向匹配）

### 3. 优化调试输出
减少冗余日志，只在状态变化时输出关键信息。

## 测试步骤

### 准备工作
1. 启动服务器
2. 打开两个客户端窗口（客户端A和客户端B）
3. 确保两个客户端都能看到控制台调试输出

### 测试场景1：A是房主，B是画手

1. **客户端A操作：**
   - 输入服务器地址和玩家名（例如：`Player_A`）
   - 点击"连接"
   - 点击"创建房间"
   - 记录房间名

2. **客户端B操作：**
   - 输入服务器地址和玩家名（例如：`Player_B`）
   - 点击"连接"
   - 点击「刷新房间列表」，选择客户端 A 创建的房间

3. **客户端A操作：**
   - 点击「开始游戏」，再点击「开始回合」

4. **预期结果：**
   - 两个客户端应收到服务端的回合开始通知，逐个确认画手身份和画布状态
   - 客户端A（如果不是画手）应该显示猜词对话框
   - 客户端B（如果是画手）应该能立即绘画

5. **检查点：**
   - [ ] 客户端A的日志显示：`*** 关键消息 *** 收到回合开始`
   - [ ] 客户端B的日志显示：`*** 关键消息 *** 收到回合开始`
   - [ ] 画手客户端显示：`*** Canvas::paintEvent - 画手可以绘画 ***`
   - [ ] 猜词者客户端显示猜词对话框
   - [ ] 画手可以立即在画布上绘画

### 测试场景2：A是房主也是画手

1. 按照场景1的步骤1-3操作

2. **预期结果：**
   - 如果客户端A是画手：A能立即绘画，B显示猜词对话框
   - 如果客户端B是画手：B能立即绘画，A显示猜词对话框

## 故障排查

### 问题：画手仍然显示"等待回合开始"

#### 可能原因1：画手客户端没有收到消息
**检查：**
- 画手客户端的日志中是否有 `*** 关键消息 *** 收到回合开始`
- 如果没有，说明服务器没有广播给所有客户端

**解决方案：**
- 检查服务器代码，确保回合开始消息广播给房间内所有玩家
- 而不是只发送给房主或猜词者

#### 可能原因2：身份判断失败
**检查：**
- 画手客户端的日志中 `onDrawerAssigned` 的输出
- 查看 `drawerId`、`m_playerId`、`m_playerName` 的值
- 查看身份判断结果 `isMe` 的值

**解决方案：**
- 如果所有判断方式都失败，可能是服务器发送的 `drawerId` 格式与客户端存储的不一致
- 在服务器端和客户端添加日志，对比ID格式

#### 可能原因3：Canvas状态设置失败
**检查：**
- 画手客户端的日志中是否有 `画布状态已更新 - roundActive: true, myTurn: true, drawer: true`
- 检查 `Canvas::canDraw()` 的输出

**解决方案：**
- 如果状态设置失败，检查 `onRoundStarted()` 函数的执行流程
- 确保没有其他地方重置了画布状态
