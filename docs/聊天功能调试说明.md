# 聊天功能调试说明

本文保留聊天功能的修复记录。日志示例的文字随客户端版本变化。初次联调请先按 [双人联机验证](../README.md#双人联机验证) 启动两个客户端。

## 问题诊断

### 修复内容

1. **移除了提前返回的问题**
   - 之前聊天消息处理在JSON解析之前就返回了
   - 现在统一在JSON解析中处理

2. **增强了消息解析**
   - 支持多种发送者字段：sender, username, player_id
   - 添加了详细的调试日志

3. **添加了错误处理**
   - 检查聊天窗口是否初始化
   - 检查连接状态
   - 显示详细的调试信息

## 测试步骤

### 1. 关闭当前运行的程序
需要先关闭PaintEngineDemo.exe才能重新编译

### 2. 重新编译
按 [构建和运行说明](../README.md#构建和运行) 重新编译客户端。

### 3. 测试聊天功能

#### 步骤A：打开聊天窗口
1. 启动程序并连接服务器
2. 点击 **"💬 聊天"** 按钮
3. 聊天窗口应该弹出

#### 步骤B：发送消息
1. 在聊天窗口输入框输入消息
2. 点击"发送"或按回车
3. 查看主日志输出：
   ```
   📤 发送: {"type":4,"message":"你的消息"}
   💬 已发送: 你的消息
   ```

#### 步骤C：接收消息
当对方发送消息时，应该看到：

**调试日志（qDebug）**：
```
消息类型: 4
收到聊天消息 - 发送者: 玩家名 消息: 消息内容
✅ 处理聊天消息 - 发送者: 玩家名 消息: 消息内容
```

**主窗口日志**：
```
📥 收到: {"type":4,"sender":"玩家名","message":"消息内容"}
💬 玩家名: 消息内容
```

**聊天窗口**：
```
[时间] 玩家名: 消息内容
```

## 可能的服务器消息格式

服务器可能发送以下格式之一：

### 格式1：带sender字段
```json
{
    "type": 4,
    "sender": "玩家名",
    "message": "消息内容"
}
```

### 格式2：带username字段
```json
{
    "type": 4,
    "username": "玩家名",
    "message": "消息内容"
}
```

### 格式3：带player_id字段
```json
{
    "type": 4,
    "player_id": "player_17",
    "message": "消息内容"
}
```

### 格式4：纯消息
```json
{
    "type": 4,
    "message": "消息内容"
}
```

代码现在支持所有这些格式！

## 调试检查清单

### ✅ 消息是否发送成功
- [ ] 主日志显示 `📤 发送: {"type":4...}`
- [ ] 主日志显示 `💬 已发送: xxx`

### ✅ 消息是否被接收
- [ ] 主日志显示 `📥 收到: {"type":4...}`
- [ ] qDebug显示 `消息类型: 4`
- [ ] qDebug显示 `收到聊天消息 - 发送者: xxx`

### ✅ 消息是否正确显示
- [ ] 主日志显示 `💬 玩家名: 消息`
- [ ] 聊天窗口显示消息

## 如果还是收不到消息

### 检查1：服务器是否转发了消息
查看对方的客户端是否发送成功

### 检查2：查看完整的JSON
在主日志中找到 `📥 收到:` 的完整JSON内容

### 检查3：确认type字段
确保消息的type确实是4，而不是其他数字

### 检查4：查看qDebug输出
在Qt Creator的"应用程序输出"窗口查看详细日志
